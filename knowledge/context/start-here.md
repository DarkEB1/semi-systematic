# Start here: how this repo works and how to engage with it

The one page to read first, whether you are a person or an agent. It tells you what the repo
looks like, what a normal week leaves behind, which page to read next, and what to do in your
first hour. Everything here is plain text in git; the only runtime is the devcontainer and the only
interface is `just` (run `just` alone to list the recipes).

## Reading order

1. This page.
2. [AGENTS.md](../../AGENTS.md): how to work, how to verify, the nine rules, autonomy. Short by design; the per-folder `AGENTS.md` files hold the rest and load when you work there.
3. [workflow](workflow.md): the story of a researcher's week and of an agent loop.
4. [walkthrough](walkthrough.md): the same week as real commands with their real output.
5. [data-access](data-access.md): how to read and write data from a notebook or a script.
6. [working-with-agents](working-with-agents.md): how to ask an agent to do something here, and how to review what it did.
7. [CONTRIBUTING.md](../../CONTRIBUTING.md): branches, PRs, CI, and how to change a convention.
8. [ADR-0001](../decisions/ADR-0001-initial-setup.md): every decision behind the layout, with the alternatives that were rejected.

## What the repo looks like

```text
semi-systematic/
├── AGENTS.md                 the rules (read second); research/, knowledge/, src/quant/, tools/ carry their own
├── README.md                 what this is, setup by hand, setup with an assistant
├── CONTRIBUTING.md           branches, PRs, CI, changing conventions
├── justfile                  the only interface: just <recipe>
├── .env.example              every variable any recipe reads (.env is yours, gitignored)
├── .devcontainer/            the only supported runtime
├── knowledge/                the team's memory (opens as an Obsidian vault)
│   ├── context/              standing picture: strategy, universe, conventions, tags, team, guides
│   ├── decisions/            ADR-NNNN-*.md, one per decision that passed the ADR test
│   ├── meetings/             YYYY-MM-DD-slug.md, minutes with checkboxed actions
│   ├── notes/<handle>/       your notes; free form, indexed, never private
│   ├── research-log/         one entry per finished experiment
│   ├── agent-log/            one entry per agent task or loop
│   ├── templates/            copy these; the checker enforces their shape
│   └── INDEX.md              generated by `just index`, never hand-edited
├── research/<project>/       a project is a folder: README.md (goal, hypotheses, status) and
│   └── experiments/<date>-<slug>/   config.yaml, run.py (marimo), results.md, figures/, outputs/ (gitignored)
├── catalog/
│   ├── catalog.sql           DuckDB views over the bucket
│   ├── datasets/<name>.md    dataset READMEs; the Schema table is the curated contract
│   └── reference/*.csv       small reference tables (universe)
├── src/quant/                data layer (read/write policy), ingest modules, promote, health, audit
├── tests/                    pytest; `just test`
├── tools/                    isolated packages, importable anywhere (contract in tools/README.md)
│   ├── brain/                retrieval index (`just index`, `just search`)
│   └── backtest/             reserved for the first reusable backtest loop; `just new-tool` adds more
├── dashboards/hub/           one marimo hub, five pages (`just dashboard`, port 2718)
├── .claude/
│   ├── settings.json         Claude Code team settings: deny rules, hooks (the zero-exception rules)
│   ├── agents/reviewer.md    read-only reviewer subagent; checks a PR against its spec before a merge
│   └── skills/<name>/        SKILL.md (the recipe an agent follows) + <name>.py (its deterministic part)
├── ai/                       prompts/ (paste-ready), evals/ (goldens), tasks/ (budgeted loops), models.yaml
├── promote/requests/         YAML requests that promote.yml executes on merge
├── scripts/                  checkers and runners behind the just recipes
│   └── hooks/                stdlib python that Claude Code runs around tool calls (wired in .claude/settings.json)
└── .github/                  CODEOWNERS, Dependabot, seven pinned workflows
```

Data never lives in git. It lives in one Cloudflare R2 bucket under three prefixes: `raw/` (written
only by the nightly ingest workflow), `curated/` (written only by the promote workflow, append-only,
schema contract) and `scratch/<handle>/` (yours, write anything). The rules are enforced in code.

## How it fits together

Everything is isolated and comes together in exactly three places: the **data layer** (the
bucket, the catalog views, `src/quant/`), the **dashboard** (`dashboards/hub/`, which reads
everything and is imported by nothing) and the **context docs** (`knowledge/`, with the index
over it). A tool, an experiment or a skill imports the data layer and tools, never another unit.
Two units that need the same result exchange it as a dataset; two experiments that need the same
function get it from a tool. `just check` enforces the import rules
([ADR-0003](../decisions/ADR-0003-isolation-principle.md)).

## What a week leaves behind

Each activity produces a fixed set of files, so the repo is readable by anyone who comes later.

| you did | the repo now has |
|---|---|
| had an idea | `knowledge/notes/<you>/<date>-<slug>.md`, tagged `idea` |
| started a project | `research/<project>/README.md` with goal, hypotheses, data, status |
| ran an experiment | `research/<project>/experiments/<date>-<slug>/` and `knowledge/research-log/<date>-<slug>.md` |
| added a data source | `src/quant/ingest/<source>.py`, `catalog/datasets/<name>.md`, a view, a test, a workflow matrix entry |
| promoted a dataset | `promote/requests/<date>-<name>.yml`, then `curated/<name>/snapshot=<date>/` in the bucket |
| held a meeting | `knowledge/meetings/<date>-<slug>.md`, plus an ADR per decision that passed the ADR test |
| asked an agent | `knowledge/agent-log/<date>-<slug>.md` linking every file it touched and relied on |
| merged any of it | `knowledge/INDEX.md` regenerated and the chunk table uploaded, so `just search` finds it |

## Your first hour (people)

1. Finish setup: [README.md](../../README.md) "Set up by hand" or the assistant block. `just onboard` must print `0 missing`.
2. `just search "strategy"` and `just search "universe"`; read [strategy](strategy.md), [universe](universe.md), [conventions](conventions.md).
3. `just dashboard`, open `http://localhost:2718`, click through the five pages ([dashboards/hub/README.md](../../dashboards/hub/README.md) explains each).
4. Open `knowledge/` as an Obsidian vault (File, Open folder as vault). Links are plain relative markdown, so any editor works too.
5. Write your first note from [the note template](../templates/note.md) into `knowledge/notes/<you>/`, run `just check`, open a PR. That PR is your onboarding.

## Your first hour (agents)

1. You are inside the devcontainer or you are in the wrong place. `just onboard` tells you.
2. Read [AGENTS.md](../../AGENTS.md) in full, then the `SKILL.md` of the skill you were asked to run. Skills live in `.claude/skills/<name>/`; in Claude Code they are the `/<name>` commands.
3. Search before acting: `just search "<topic>"`, two or three phrasings.
4. Do the task through `just` recipes only. Write data only under `scratch/<handle>/`. Never rename or move anything under `knowledge/`.
5. End with an agent-log entry from [the template](../templates/agent-log.md), `just check` and `just test` green, and a PR. Merge it yourself only when CI is green and no changed path is under the data-layer CODEOWNERS block (`src/quant/data/**`, `catalog/**`, `promote/**`, `.github/**`).

## Where to ask

There are no chat notifications. Questions and problems are GitHub issues; proposals are PRs;
decisions are ADRs. `just where "<thing>"` answers "where does X go" from the repo itself.
